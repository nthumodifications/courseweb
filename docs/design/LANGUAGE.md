# NTHUMods 設計語言

可執行的規則。`PHILOSOPHY.md` 說「為什麼」，這份說「怎麼做」。

每一條規則後面都附了它的出處——產品裡哪一個檔案已經這樣做了。**規則不是我發明的，是從旗艦頁面量出來的。**

> 兩個旗艦檔案：
>
> - 校車 `apps/web/src/app/[lang]/(mods-pages)/bus/page.tsx`
> - 課表 `apps/web/src/app/[lang]/(mods-pages)/timetable/page.tsx`
>
> 這兩個檔案是規格。規則跟它們衝突時，以它們為準。

---

## §1 頁面骨架

```tsx
// 正確：校車頁的骨架
<div className="flex flex-col px-4">
  {/* 控制列（如果有） */}
  {/* 內容 */}
</div>
```

**規則**

1. 頁面根元素是 `flex flex-col`，水平內距 `px-4`（桌機可 `md:px-6`）。
2. **沒有 `mx-auto`。沒有 `max-w-*` 置中欄。** 頁面用滿可用寬度。側邊欄已經決定了左邊界。
3. **沒有 `<main>`**——`SidebarInset` 已經提供了。巢狀 landmark 是無障礙錯誤。
4. 頁尾留白用一個明確的 `<div className="h-6" />`，不要靠 `pb-12`。
5. 有底部導覽列時（手機），底部內距要算進 `--bottom-nav-height` 和 `env(safe-area-inset-bottom)`。

**禁止**：`max-w-3xl mx-auto`、`items-center` 當版面手段、`justify-center` 當版面手段、`text-center` 出現在任何頁面層級。

---

## §2 頁面標題：預設不要

**預設情況：頁面沒有標題。** 校車、課表都沒有。

要加 `PageHeader`，必須同時滿足：

- 這一頁的內容**不會自己說出它是什麼**（例如一個純表單、一個設定分頁）；**而且**
- 側邊欄的當前項目不足以說明（例如這是一個從別處跳進來的子頁）。

加了標題也**不准加 `description`**。

> 上一版把 `description` 加到幾乎每一頁，寫出「你的行事曆、課表與校務日期會顯示在這裡」這種句子。那是在解釋一個使用者正在看的東西。全部刪掉。

**唯一合法的 `description`**：傳達使用者**不可能從畫面上推得**的事實。例如「資料每 5 分鐘更新」、「僅顯示本學期」。不是「這是你的課表」。

**頁內動作**：優先用 header portal（`useHeaderPortal`），像課表頁把學期切換器送進共用 header 那樣。次選是放在控制列。不要為了擺一顆按鈕而生出一個 page header。

## §3 間距：只有四個值

從旗艦頁量出來的完整詞彙：

| 值   | class                    | 用在哪                             | 出處                      |
| ---- | ------------------------ | ---------------------------------- | ------------------------- |
| 4px  | `gap-1`                  | 圖示與緊貼的標籤                   | 少見                      |
| 8px  | `gap-2` / `px-2`         | 列內次要元素、列表內縮             | 校車備註列、`divide` 容器 |
| 16px | `gap-4` / `p-4` / `py-4` | 主要節奏：列高、頁面內距、區塊間距 | 校車列、課表格線          |
| 24px | `h-6`                    | 大段落之間、頁尾                   | 校車頁尾                  |

再加一個給密集控制項的 12px（`gap-3`／`py-1.5` 這類）——側邊欄的導覽項、工具列、可拖曳排序的列，本來就比內容列緊。

**上限是這些。** 沒有 `py-12`，沒有 `space-y-8`，沒有 `my-16`。

如果你覺得需要更大的間距，通常是因為版面置中了、或是加了不該有的標題。先修那個。

### 這條規則只能往下，不能往上

**絕對不要為了「符合間距表」把原本緊湊的東西改鬆。**

這條規則的目的是擋掉 `py-12`、`space-y-8` 那種膨脹，不是把密集的介面撐開。上一輪有人把側邊欄導覽從 `gap-3 py-1.5` 改成 `gap-4 py-2`，只因為 3 和 1.5 不在表上——結果是導覽變鬆了，而且沒有人要求這件事。那是規則被反向套用。

判斷方式很簡單：**改完之後，畫面上的資訊變多還是變少？** 變少就是改錯了。密度是功能（見原則 4）。

同理，一個可拖曳排序的列，它的上下箭頭必須**貼著它排序的那一列**。把箭頭用間距推開，會讓使用者看不出這兩顆按鈕在排序哪一行。控制項的內部間距由「摸得到、看得懂」決定，不由這張表決定。

**列高**：一列內容是 `py-4`。兩列之間不再加 margin——`divide-y` 負責分隔。

**密集控制列**：如果一列包含 40px 的拖曳把手、開關或其他控制項，使用
`gap-2 py-2`。`py-4` 會把設定清單撐鬆，不能為了套用主要內容列的節奏而增加
控制列高度。

## §4 列表：一條線，不是一張卡

這是產品最重要的版面單元——**但它有前提。**

### 先決定該不該用列表

校車的列之所以撐得起整個寬度，是因為**它的右邊有答案**：

```
紅線                                                    2 min
```

左邊是身分，右邊是答案，中間的 `flex-1` 把兩端拉開。兩端都有東西，這一列才成立。

**如果一列的右邊沒有答案，它就不該是一列。**

一個功能清單（`/apps`）的項目只有圖示和名稱，右邊沒有時間、沒有數字、沒有狀態。把它做成整頁寬的列表，等於左邊 300px 有內容、右邊 1000px 全是空白——每一列都是一條孤零零的短句拖著一大片空地。這比卡片還糟。

| 情況                                                                 | 用什麼                           |
| -------------------------------------------------------------------- | -------------------------------- |
| 每一項右邊都有一個**答案**（時間、數量、狀態、剩餘名額）             | `divide-y` 列表，撐滿寬度        |
| 每一項是**同級的入口**，右邊沒有答案（功能清單、分類選單、主題選擇） | 網格（grid），桌機多欄           |
| 窄容器裡（對話框、側欄、手機）                                       | 列表——因為寬度本來就不夠開成網格 |

所以 `/apps` 在手機上是列表、在桌機上是多欄網格，這不是妥協，是同一條規則在不同寬度下的正確結果。「不要用卡片」的意思是不要**為了分隔**而包卡片，不是「所有東西都必須排成一條直線」。

### 列表的寫法

```tsx
// 校車頁，逐字照抄的結構
<div className="flex flex-col px-2 divide-y divide-border">
  {items.map((item) => (
    <div className="flex flex-col gap-4 py-4">
      {/* 主列：身分在左，答案在右 */}
      <div className="flex flex-row items-center gap-4">
        <Icon className="h-7 w-7" />
        <h3 className="text-foreground font-bold">{title}</h3>
        <div className="flex-1 text-right font-bold whitespace-nowrap">
          {value}
        </div>
        <ChevronRight className="w-4 h-4" />
      </div>
      {/* 次列：動作與備註 */}
      <div className="flex flex-row gap-2">…</div>
    </div>
  ))}
</div>
```

**列的解剖**

| 位置 | 內容                      | 樣式                                     |
| ---- | ------------------------- | ---------------------------------------- |
| 最左 | 識別圖示                  | `h-7 w-7`（有品牌意義時）或 `h-4 w-4`    |
| 左   | 這一列是什麼              | `font-bold text-foreground`              |
| 中   | —                         | `flex-1`，空的。把答案推到右邊           |
| 右   | **答案**                  | `text-right font-bold whitespace-nowrap` |
| 最右 | 可進入時的 `ChevronRight` | `w-4 h-4`                                |

最左的識別項必須是有意義的資料或操作圖示。不要為了填補欄位加一個裝飾性的點、
方塊或色塊。課程的學分是課程標籤列的一部分，不是被抽離成另一個右側答案；
課程列表和課程詳情都要保留同一份學分資料。

**次列**（選用）：動作與備註，`text-sm font-medium`，圖示 `w-4 h-4`，`gap-2`。中文備註之間用全形間隔號 `・`。

**規則**

1. 列表用 `divide-y divide-border`。**不要每一列包一張卡片。**
2. 答案永遠靠右且 `whitespace-nowrap`。時間、數字、狀態不能換行。**右邊沒有答案的東西，回去看本節開頭——它應該是網格。**
3. 不適用的列用 `opacity-30` 降級，**不要移除**。（校車頁對收班路線就是這樣做的。）
4. 整列可點擊時，`cursor-pointer` 放在可點的那一層，不是整個容器。

## §5 表面：三層，只有一層有影子

| 層   | 用途                  | 樣式                                                  |
| ---- | --------------------- | ----------------------------------------------------- |
| 1 底 | 頁面本身              | `bg-background`，無邊框無影子                         |
| 2 面 | `Section`、卡片、面板 | `bg-card border border-border rounded-lg`，**無影子** |
| 3 浮 | 真的浮在畫面上        | 有影子                                                |

第 3 層的完整清單：`Dialog`、`Popover`、`DropdownMenu`、`Drawer`、`Sheet`、`Toast`、地圖上的浮動搜尋卡。**沒有別的。**

其他任何地方出現 `shadow-*` 都是錯的。

**卡片的門檻**：一張卡片要能回答「它圍住了哪一個完整的東西」。圍住一段文字、圍住一個空狀態、圍住一個標題——都不算。

## §6 顏色：只用 token

1. **禁止硬寫顏色**：沒有 `#hex`、`rgb()`、`text-gray-500`、`bg-neutral-800`、`border-slate-200`。
2. **禁止 `dark:` 覆寫。** token 自己會在 `.dark` 下換值。寫 `dark:` 表示這個顏色沒有走 token。
3. **品牌紫 `nthu-*` 只用在**：即時／現在／緊急的值（校車的「即將發車」）、主要動作按鈕、當前選取狀態。不當背景塊，不當裝飾。
4. **語意 token**：`foreground` / `muted-foreground` / `background` / `card` / `border` / `destructive` / `primary`。文字只有兩級：`text-foreground`（內容）和 `text-muted-foreground`（後設資訊）。

**合法例外（資料色，不是樣式色）**——這些要走 `tools/design-lint/` 的白名單，不要硬塞進 token：

- 校車路線色（紅線真的叫紅線）
- 課表色票（使用者選的）
- 行事曆事件色（使用者為事件選的）
- `no_class` 斜線底紋
- 天氣圖示

資料色不能只存在資料模型裡而在列表中消失。行事曆的事件列表至少要保留一個
使用事件色的識別條；把事件色換成通用的灰色標籤會丟失使用者建立的視覺分類。

---

## §7 字級：產品最大的字是 `text-base`

把校車頁和課表頁翻一遍，**沒有任何一個 `text-xl`、`text-2xl`、`text-3xl`、`text-4xl`。**

最大的字是預設大小加 `font-bold`——就是那個路線名和那個發車時間。

| 用途                     | class                                                    |
| ------------------------ | -------------------------------------------------------- |
| 列的主要內容／答案       | `font-bold`（預設字級）                                  |
| 一般內文                 | 預設字級                                                 |
| 備註、次要動作、後設資訊 | `text-sm font-medium` 或 `text-sm text-muted-foreground` |
| 極次要（很少用）         | `text-xs text-muted-foreground`                          |

**規則**

1. `text-xl` 是全站上限，而且只給真的需要標題的頁面。`text-2xl` 以上一律禁止。
2. **粗細只有 `font-medium` 和 `font-bold`。** 不要 `font-semibold`——中文字型多半沒有這個字重，瀏覽器會合成假粗體，邊緣會糊。（見 §8）
3. 階層用**粗細和顏色**做，不要用字級做。校車頁整頁只有一個字級。

## §8 繁體中文排版

產品的母語是繁體中文（台灣）。所有版面先在中文下成立。

**禁止的工具類**

| 類別                                              | 為什麼                                                 |
| ------------------------------------------------- | ------------------------------------------------------ |
| `uppercase` / `lowercase` / `capitalize`          | 中文沒有大小寫。混排時只會影響英文，造成不一致         |
| `italic`                                          | 中文沒有斜體，瀏覽器會做幾何傾斜，很醜                 |
| `tracking-tight` / `tracking-tighter`             | 中文字本來就滿格，收緊會黏在一起                       |
| `text-balance` / `text-pretty`                    | 中文可在任意字間斷行，本來就會排平                     |
| `hyphens-*` / `break-words`                       | 中文不連字                                             |
| `font-semibold` / `font-light` / `font-extrabold` | 中文字型通常只有 Regular / Medium / Bold。其他會被合成 |

**要做的**

1. **字重只用 `font-normal` / `font-medium` / `font-bold`。**
2. **行高放鬆。** 中文內文至少 `leading-relaxed`（1.625）。字級可以小，行高不行。列表列裡的單行文字不受此限。
3. **少截斷。** `truncate` 在中文會切在語意中間。優先給空間、換行、或縮短字串本身。真的要截斷才用。
4. **全形標點，而且各司其職。**
   - `，` 句中停頓；`。` **句子結束**；`、` 並列的詞
   - `・` 是**間隔號**，只用來分隔並列的短項目或外文人名（校車頁的備註分隔就是這個用法）
   - **不要用 `・` 當句號。** 產品裡目前有「課程搜尋發生錯誤・此請求未改用其他搜尋層級重試・」這種字串，兩個 `・` 都應該是 `。`
   - 不要用 `,` `.` `|` `-` `~` 當中文的標點。半形波浪號 `~` 尤其常被誤用在句尾
5. **中英數混排**：字型堆疊要讓拉丁字母走 Inter、中文走 PingFang TC / Noto Sans TC。順序不能反。
6. **寫中文文案時先問：這句話在中文裡是不是已經完整了？** 中文用四五個字講完的事，通常不需要第二句解釋。「今天沒有課」就是完整答案，後面不要再接一句話。

**文案**

- 簡短、直述、不寒暄。「找不到課程」不是「哎呀！我們似乎找不到任何課程 😢」。
- 不解釋畫面上看得到的東西。
- 每一個面向使用者的字串都要同時存在於 `dictionaries/zh.json` 和 `en.json`。**不准在 JSX 裡硬寫中文或英文。**
- 英文是翻譯，不是原文。如果英文比中文長很多，通常是中文那句已經夠好，英文在囉嗦。

## §9 控制項

**分頁（Tabs）** —— 校車頁的寫法就是標準：

```tsx
<TabsList className="w-full justify-evenly mb-4">
  <TabsTrigger className="flex-1" value="…">
    …
  </TabsTrigger>
</TabsList>
```

滿寬、等分、`mb-4`。不要置中一組縮在中間的分頁。

**按鈕**

- 一個畫面只有一個 primary。其餘 `variant="outline"` 或 `variant="ghost"`。
- 圖示按鈕 `w-4 h-4` 圖示。
- 一排動作要有共同節奏——不要有一個孤零零被推到右邊（課表分享列的「社群」就是這個毛病）。

**選取狀態**：用 `border-border border` 或 token 背景表示，不要用硬寫的 hover 顏色。

**觸控目標**：至少 40px 高。

## §10 零狀態

先讀 `PHILOSOPHY.md` 原則 2。

**順序**

1. **先問這個畫面的「零」有沒有結構。** 有的話，把結構畫出來。校車頁在沒有班次時仍然列出四條路線並標 `末班車已過`——這才是答案。
2. 沒有結構、真的無話可說時，才用 `EmptyState`。

今日頁的天氣是每一天的資料，不是可任意丟掉的裝飾。空課表日期仍有天氣資料時，
不要把該日期併入無內容的折疊列；保留日期標題和天氣，讓使用者看得到這份資料。

**`EmptyState` 的形狀**

- **靠左。** `items-start text-left`。**預設不是置中。**
- 緊湊：圖示 `h-4 w-4` 與標題同一行，標題 `text-sm font-medium`，垂直內距不超過 `py-4`。
- **`description` 預設不存在。** 只有在傳達畫面上推不出來的事實時才寫（「資料每 5 分鐘更新」可以；「你的課表會顯示在這裡」不行）。
- 跟周圍內容用同一個左邊界。不要縮排、不要加卡片、不要加邊框。

**置中的大型空狀態只有一個合法場合**：整個視窗都是這個狀態、而且使用者必須做一個動作才能前進（例如未登入的聊天頁）。這是例外，不是預設。

## §11 載入與錯誤

**載入**：骨架屏要跟真實內容**同形**——同樣的列高、同樣的欄位位置。不同形的骨架屏比 spinner 還糟，因為它會讓版面跳動。

單一區塊可以用 spinner（校車頁就是），但不要讓整頁只剩一顆轉圈。

**錯誤**：任何 `useQuery` 都要處理 `error`。永遠轉圈的頁面是 bug。用共用的 `ErrorState`：一句說明 + 一顆「再試一次」。跟 `EmptyState` 同形、同樣靠左。

---

## §12 不准動的東西

1. **校車頁**（`bus/` 底下全部）。唯一允許的改動是把硬寫顏色換成 token，而且要在報告裡說明。
2. **課表格線**（`components/Timetable/Timetable.tsx` 及其 slot 渲染）。完全不動。
3. **版面結構**。這一輪的工作是讓其他頁面**向旗艦靠攏**，不是重新發明版面。搬動一個區塊之前，要說得出它現在違反了上面哪一條規則。

「順手改得更好看」不是理由。

## §13 贊助與外部區塊

`OpenCollectiveSponsorBanner` 放在內容之後、頁尾之前，用 `h-6` 隔開（校車頁的做法）。它不是卡片，不加影子，不搶主色。
