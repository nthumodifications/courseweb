# NTHUMods 設計哲學

## 這份文件的來源

這份哲學**不是憑空設計的**。它是從產品裡已經做對的兩個頁面反推出來的：

- **校車頁** `apps/web/src/app/[lang]/(mods-pages)/bus/page.tsx`
- **課表頁** `apps/web/src/app/[lang]/(mods-pages)/timetable/page.tsx`

這兩頁是旗艦。它們不是「符合設計系統的頁面」——它們**就是**設計系統。當這份文件和那兩個檔案衝突時，以檔案為準，然後回來改這份文件。

任何改動如果讓其他頁面**離這兩頁更遠**，就是錯的，不管它看起來多「乾淨」。

---

## 一句話

**NTHUMods 是「校園，已解答」(The campus, answered)。**

學生打開 NTHUMods 不是為了「使用一個 app」。他是站在北大門、手裡拿著手機、想知道**紅線幾分鐘後來**。他是在選課週、想知道**這門課跟我禮拜二的課衝不衝堂**。

他要的是答案，不是介面。

介面每多一層，答案就晚一秒。

---

## 五個原則

### 1. 直接給答案（不要開場白）

看校車頁。它**沒有標題**。沒有「校車時刻表」這行字，沒有副標題，沒有卡片。
`<div className="flex flex-col px-4">` 之後第一個東西就是分頁標籤，再下來就是班次。

課表頁也一樣。沒有標題，學期切換器被 portal 送進共用的 header，剩下的整個畫面就是那張格子。

**為什麼對**：側邊欄已經告訴使用者他在哪一頁了。頁面再寫一次標題，是在回答一個沒有人問的問題。副標題更糟——它在解釋一個使用者正在看的東西。

**規則**：

- 頁面預設**沒有** `PageHeader`。要加標題，必須說得出使用者在哪個情況下會不知道自己在哪一頁。
- **禁止說明性副標題。**「你的行事曆、課表與校務日期會顯示在這裡」這種句子，是把學生當笨蛋。
- 如果一段文字刪掉之後，畫面的意思沒有變——它本來就不該在。

### 2. 永遠有答案（空狀態是設計失敗）

校車頁最重要的一段程式碼，是 `// filler for no service busses`。

半夜兩點打開校車頁，資料是空的。但畫面不是空的——它把紅線、綠線、校區一號、校區二號**全部列出來**，每一條後面寫 `末班車已過`，整列 `opacity-30`。

它沒有丟一個「目前沒有班次」的空白版面給你。它回答了你真正的問題：**「還有車嗎？」→「沒有了，四條線都收班了。」**

**為什麼對**：空狀態幾乎永遠是「我們沒想清楚這個情況下的答案是什麼」的代稱。使用者問了問題，「沒有資料」不是答案。

**規則**：

- 寫空狀態之前，先問：**這個畫面的「零」有沒有結構？** 校車的零是四條線都收班了。課表的零是一週七天都沒課。行事曆的零是這段期間沒有活動。**把結構畫出來，比畫一個空盒子有用。**
- 真的需要空狀態時，它是**一行字**，靠左，跟周圍內容同一個節奏。不是置中的紀念碑。
- 用 `opacity` 降級，不要隱藏。存在但不適用，跟不存在，是兩件事。

### 3. 左起，向下（注意力的物理）

使用者的視線從左上出發，往下走。我們有側邊欄——版面的左邊界已經被定義了。

課表頁是 `grid-cols-[3fr_2fr]`：主體在左，而且更大；輔助在右。校車頁的每一列是「圖示 → 路線名 → `flex-1` → 時間（靠右）→ 箭頭」。身分在左，答案在右，中間用彈性空白推開。

**為什麼對**：置中版面是給沒有導覽列的著陸頁用的。我們有側邊欄。內容置中之後，使用者的視線要先跳過一段空白才能找到第一個字——而且空的頁面置中之後會顯得更空、更慘。

**規則**：

- **一律靠左。** 沒有 `mx-auto`，沒有 `text-center`，沒有 `items-center` 當版面手段。
- 沒有 `max-w-3xl` 之類的置中閱讀欄。頁面用滿寬度。
- 置中只有兩個合法用途：單一控制項內部的圖示對齊文字，以及真正浮在畫面上的對話框。

### 4. 一條線就夠（不要用卡片切東西）

校車頁的班次列表是 `divide-y divide-border`。沒有卡片，沒有邊框，沒有陰影，沒有圓角盒子。就是一條 1px 的線把兩列分開。

**為什麼對**：卡片是一種很貴的分隔手段。每張卡片都要付出邊框、內距、圓角、以及卡片之間的間隙——四份視覺成本，只為了說「這兩個東西不一樣」。一條線就能說完，而且省下來的垂直空間可以多放兩班車。

密度是功能，不是缺陷。學生站在公車站牌前滑手機，能一眼看到四條線，比看到一條線配大量留白有用。

**規則**：

- 右邊有答案的東西用 `divide-y divide-border` 列表。右邊沒有答案的同級入口（功能清單那種）用網格——整頁寬的列表配一個短標籤，只會做出一大片空白。細節在 `LANGUAGE.md` §4。
- 表面只有三層：頁面底色、`Section`／卡片、真正浮起來的東西（對話框、popover、下拉選單、抽屜、toast、地圖上的搜尋卡）。只有第三層有陰影。
- 卡片要能說出它「圍住了什麼一個完整的東西」。圍住一段文字不算。

### 5. 紫色是「現在」（不是裝飾）

校車頁裡 `text-nthu-500` 只出現在一個地方：某班車**即將發車**的時候。

整頁其他地方——路線名、時間、備註、分頁標籤——都是 `text-foreground` 或 `text-muted-foreground`。

**為什麼對**：如果紫色到處都是，紫色就什麼都不是。它在校車頁有意義，正是因為整頁只有它是紫的，而它代表「這班你再不跑就趕不上了」。

**規則**：

- 品牌紫保留給：即時／現在／緊急的值，以及主要動作按鈕。
- 不用紫色當背景色塊、當裝飾漸層、當「這個區塊很重要」的標記。
- 資料本身的顏色不算違規——紅線是真的叫紅線，課程色票是使用者選的。那些是資料，不是樣式。

## 6. 這個產品是用繁體中文寫的

這不是第六個原則，這是前五個原則的前提。

NTHUMods 的母語是**繁體中文（台灣）**。英文是翻譯版。所有的版面、字級、行高、間距，都要先在中文下成立，英文跟著走。

中文對版面的影響是實質的，不是換字串而已：

- **中文用更少的字說完同一件事。**「今天沒有課」五個字就是完整句子。這正是副標題在中文版裡特別多餘的原因——英文的 "No class today" 還可能需要補充，中文的「今天沒有課」不需要。
- **中文沒有大小寫，沒有斜體。** `uppercase`、`italic`、`capitalize`、`tracking-wider` 這些工具在中文下不是沒效果就是難看。
- **中文可以在任何字之間斷行。** 不需要 `text-balance`、`hyphens`、`break-words` 來救。反過來，`truncate` 在中文下會切在很尷尬的地方，能不截斷就不要截斷。
- **中文需要比較鬆的行高。** 密的字面配密的行距會糊成一塊。字級可以小，行高不行。
- **中文的粗體只有「粗」跟「不粗」。** 中文字型通常沒有 semibold，瀏覽器會用合成的假粗體，邊緣會糊。校車頁用的是 `font-bold` 和 `font-medium`——那是對的。
- **標點是全形的。** 校車頁的備註用 `・` 分隔，那是中文排版裡正確的間隔號，不是 `·` 也不是 `|`。

詳細規則在 `LANGUAGE.md` §8。

## 什麼時候不要改東西

這份文件存在的原因之一，是上一版設計工作把校車頁改壞了——在沒有實際看過它跑起來的情況下，替它加了標題、副標題和卡片，把產品做得最好的一頁拆掉了。

所以：

- **校車頁和課表頁是不動的。** 不是「盡量不動」，是不動。要碰它們，只能是把硬寫的顏色換成 token，而且要說明為什麼。
- 其他頁面的目標**不是變好看**，是**變得跟這兩頁一樣**。
- 「重新設計」不是目標。如果一個改動沒辦法用「這讓它更接近校車頁」來解釋，就不要做。

## 檢查一個畫面的四個問題

1. 使用者來這一頁是要問什麼問題？**答案在第一屏的左上角嗎？**
2. 有沒有任何一段文字，刪掉之後意思不變？**刪掉。**
3. 這一頁的「零」長什麼樣子？**有結構嗎，還是一個空盒子？**
4. 把這一頁跟校車頁並排放，**看得出來是同一個產品嗎？**
