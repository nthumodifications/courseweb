# AI core implementation report

## Changed

- Added `services/api/src/ai/llm.ts`, a provider chain for Gemini, Groq, and Workers AI.
  - Gemini uses structured response schemas and inline PDF data.
  - Groq uses the OpenAI-compatible chat endpoint, JSON mode, tool schemas, and streamed tool-call delta accumulation.
  - Workers AI uses JSON/tool inputs and `toMarkdown` for PDF conversion when available.
  - Added provider/model ordering, environment model overrides, error classification, short-lived dead-provider caching, schema validation, user-Gemini-key precedence, and the coded chat SSE event types.
- Rewired `/chat` to the provider chain while retaining auth, removed the stale experimental Gemini model, added `meta` and coded `error` SSE events, and stopped manually overriding global CORS headers.
- Added unauthenticated `POST /ai/test-key` and `GET /ai/status`.
- Reworked syllabus summaries onto `generateJSON`, including cache-miss IP rate limiting, provider/model response metadata, bilingual workload normalization, bullet limiting, difficulty clamping, PDF input, and 503 handling for provider/cache failures.
- Reworked PEO schedule PDF parsing onto the provider chain and preserved existing non-null cached hours when a forced/new parse fails.
- Added the Workers AI binding and `AI_RATE_LIMITER` to Wrangler configuration and updated environment typing/CORS for `X-Gemini-Api-Key`.
- Secured the existing manual sports refresh trigger with `PEO_REFRESH_SECRET` and `X-PEO-Refresh-Secret`; the scheduled sync remains available without that secret.
- Added focused unit tests for classification, fallback ordering, schema conversion/validation, Groq tool deltas, and summary normalization/clamping.
